# Sky 研究與模擬交易：無券商帳戶政策 V1（2026-11-10）

## 已確認事實與優先原則

使用者目前**未開立證券交易帳戶**。Sky 在研究、行情取得、當沖／波段掃描、模型驗證、GitHub 排程、指令輸出、Shadow、Paper 與模擬交易績效評估階段，**不得要求先開戶、確認券商、確認券商 API、或提供個人真實持倉／委託／成交帳本**。

以上不是研究資料品質、策略獲利能力、可用行情覆蓋率、風險控制、或模擬交易效能的替代證明。不得以不存在的券商帳本資料當成 0 持倉、0 損益、0 滑價。

## 適用於所有模組與指令

- 各種 Sky 當沖、快掃、波段、Swing、警戒、全球盤前、全市場覆蓋率、個股分析、六模型研究、回測、研究驗收、排程及手機輸出：只使用可得的行情、策略證據、歷史／前瞻觀察，不得把券商連線當成執行前置條件。
- P0-R 研究／PAPER_ONLY：以有來源與時間戳的**模擬帳本**驗證兩次停損、當日累計淨損、每筆資金風險、部位上限、停損失效與成本後 RR；缺紙上帳本或成本證據需標 `INSUFFICIENT_DATA`，不能冒稱通過，但不阻礙研究資料蒐集。
- PAPER_ONLY 的訊號、假設成交時間、成交方法、完整費稅與滑價估計、驗證結果需逐筆記錄；若沒有充分證據不產生虛構成交或統計淨損益。
- 現有 `src/main.py` 的正式實盤風控、`src/risk_engine.py`、W6 PR #365、W3B PR #488 等原治理工作保留研究／正式交易邊界；未獲准不得升級 Production。
- GitHub Actions 每五分鐘排程的可靠性只以實際 schedule event、執行日誌、下游報告、資料時間與故障訊息確認；與個人券商開戶無關。

## 僅未來實際要開啟真實交易時

目前一律 `NO_LIVE_TRADING`、`production_eligible=false`、`automatic_order=false`。

將來若使用者另行決定開戶並正式要求實盤，才獨立核對券商帳戶授權、持倉與委託／成交資料來源、券商契約費率、真實風控與 W0/P0-G 審查。**此未來實盤條件不得反向阻斷任何現在的研究、Paper 或行情指令。**

## 狀態分類

`RESEARCH_AVAILABLE`：能進行行情觀察／策略研究，不需真實帳本。

`PAPER_INPUT_REQUIRED`：模擬帳本、模擬信號、假設成交或成本不完整，只阻擋模擬績效／模擬新進場判定，研究本身繼續。

`LIVE_TRADE_DISABLED`：始終不自動下單，非故障、非研究阻礙。

`INSUFFICIENT_DATA`：缺必要證據時明確說明，不杜撰數值，也不移除完整風控驗證標準。
